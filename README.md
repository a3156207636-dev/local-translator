打中文的时候，旁边一个悬浮窗同步显示英文对照。原文不变、发出去的还是中文，
只是让你在打字的同时看到对应的英文表达。

**整条链路只在本机运行**，翻译请求只发往 `127.0.0.1`，不经过任何外部服务器。

---

## 它能做什么

- **按键即弹出** —— 只要按下第一个字符，悬浮窗**立刻**出现在光标旁（实测 **55 ms**），不用等翻译完
- **译文逐字浮现** —— 流式输出，本地模型**首个英文字符 20～25 ms** 就出现，整句约 150～180 ms
- **不自动消失** —— 窗口一直留在屏幕上，直到你自己点「×」或按 `Esc`；打字时也不会把它藏起来
- **开机自动启动** —— 开机登录后自动在后台待命，右下角常驻状态球，不用手动开
- **手动快捷键** —— 默认 `Ctrl+Alt+T`，翻译当前选中的文字（可在设置里改成翻译剪贴板）
- **完全离线** —— 模型跑在本地显卡上，断网可用，没有服务商侧的限流、封禁或内容审核
- **不打断输入** —— 悬浮窗加了 `WS_EX_NOACTIVATE`，永远不抢焦点，不会中断中文输入法
- **自动接管引擎** —— 启动时发现 Ollama 没在跑，会自己把它拉起来
- **兼容任何本地推理服务** —— Ollama、LM Studio、llama.cpp、vLLM、OneAPI 等 OpenAI 兼容端点

## 开机自启

已经帮你开好了（注册表项 `HKCU\...\Run\LocalBilingualTranslator`）。
登录后它用 `pythonw.exe` 启动，**不会闪出黑色控制台窗口**，会先等桌面（explorer）就绪，
然后自动拉起 Ollama、预热模型，最后挂在后台待命。

三种方式都能开关：

| 方式 | 操作 |
|---|---|
| 批处理 | 双击 `autostart-on.bat` / `autostart-off.bat`（会打印当前状态） |
| 状态球 | 右键状态球 → 勾选/取消「开机自动启动」（立即生效） |
| 设置窗口 | 右键状态球 → 打开设置 → **启动** 分组 → 开机自动启动 |

命令行等价写法（输出是 ASCII 键值，方便脚本解析）：

```
.venv\Scripts\python.exe main.py --set-autostart on     # -> AUTOSTART=ON
.venv\Scripts\python.exe main.py --set-autostart off    # -> AUTOSTART=OFF
.venv\Scripts\python.exe main.py --autostart-status     # -> AUTOSTART=ON / OFF + COMMAND=...
.venv\Scripts\python.exe main.py --running              # -> RUNNING / STOPPED（退出码 0 / 1）
```

想让登录后多等几秒再启动（避开开机高峰），在设置里把「登录后额外等待（秒）」改成 3～10 即可。

> 自启项指向的是当前这个目录，**别把 `local-translator` 文件夹挪走或删掉**，否则自启会失效。
> 如果确实要挪，挪完重新双击一次 `autostart-on.bat` 即可（它会自动写入新路径）。
>
> 批处理文件名是中文，但**文件内容是 GBK 编码**（匹配简体中文控制台的代码页 936），
> 所以双击后中文提示能正常显示。用编辑器打开时记得选 GBK，否则会看到乱码。

## 工作原理

```
按键（任意字符）
     → 全局键盘钩子：立刻通知界面「打字了」→ 悬浮窗原地弹出（约 55 ms）
     → UI Automation 读取当前焦点输入框里已上屏的中文
     → 截取最后一句
     → 停顿 300 ms → POST 到 127.0.0.1 上的本地模型（流式）
     → 首个英文字符 20~25 ms 后开始逐字浮现，整句约 150~180 ms
```

几个关键设计：

- **窗口先出现，译文后到。** 键盘钩子一感知到按键就让悬浮窗先弹出来，不等翻译结果——
  否则用户会觉得「打了半天没反应」。译文到了再原地刷新，不闪、不跳。
- **流式输出。** 走 SSE / NDJSON 流，译文逐字写入，体感远快于「等整句算完再显示一次」。
- **键盘钩子不负责取字。** 中文输入法上屏的汉字从原始键值里拿不到（钩子只看到拼音字母），
  所以钩子只当「打字活动信号」，真正的文本由 UI Automation 从焦点控件读。
- **会先判断焦点是不是输入框。** 浏览器类应用（抖音、B 站等）里，焦点有时会落到
  整个网页文档上，这时 UIA 会把**整页文字**（按钮、点赞数、别人的评论、播放进度）
  一起交出来。读到的原文里如果同时出现多个界面标志物（`展开`/`加载中`/`超清`/`连播`
  这类按钮词，配合 `00:00 / 34:30` 时间戳、`2.0x` 倍速、`2.0万` 计数），
  就判定焦点不在输入框上，**静默跳过不翻译**，避免「把整个评论区翻译一遍」。
  规则见 `context_reader.looks_like_ui_noise()`，回归用例见 `test_noise.py`。
- **读取三级降级。** UIA 的 `TextPattern`（能拿到光标前的精确文本）→ `ValuePattern`（标准输入框、浏览器
  `<input>`/`<textarea>`）→ Win32 `WM_GETTEXT`。任何一级拿到就停。
- **取最后一句按句末标点切。** 不会在逗号处误切——`"今天不错，我们走吧。"` 会整句送出，
  而 `"第一句。第二句！第三句？"` 只送 `"第三句？"`。
- **不抢焦点。** 悬浮窗用 `overrideredirect` + `WS_EX_NOACTIVATE`，Windows 层面就不会激活它。
- **固定宽度。** 每次都用配置里的宽度渲染，避免刚弹出时（原文还空着）窗口很窄、内容到了又猛地变宽。
- **强制直连，不走代理。** HTTP 会话设了 `trust_env = False`。否则系统里的 `http_proxy`
  会把本该发往 `127.0.0.1` 的请求绕到代理上——既可能失败，也违背「数据不出本机」的前提。
- **冷启动处理。** 启动时预热一次把模型读进显存，并对超时自动重试一次，
  所以第一次真实翻译也是秒出，不用等几十秒。
- **引擎没起来就快速失败。** 否则本地端口不拒绝连接、只静默丢弃，请求会一直挂到超时，
  表现成「打了字什么反应都没有」。
- **队列驱动。** 键盘监听和翻译都在后台线程，所有界面操作通过队列投递到 tkinter 主线程执行。

## 常见问题

**双击 `启动.bat` 之后什么都没发生？**
先看**屏幕右下角**（任务栏上方、靠右侧）有没有一个小圆球「译 · 待机」。
有就是启动成功了，悬浮窗只在你打字停顿后才出现。没有的话用 `调试启动.bat` 看报错。

**悬浮窗为什么一直不出来？**
它在**你按下第一个键的瞬间**就该出现了（实测 55 ms）。如果没出现：
确认状态球在、焦点在真正的输入框里、设置里「按下第一个字就弹出窗口」是勾上的。
想让它别再自动弹，把这个开关取消勾选即可——那时只在你**停止打字约 0.3 秒后**才出现。

**它挡住东西了 / 我不想让它一直在？**
点窗口上的「×」或按 `Esc` 关掉（本次输入中途不会再自动弹）。
也可以把设置里的「自动隐藏（毫秒）」改成 `3000` 之类，让它自己淡出；
或者把「再次打字时隐藏窗口」勾上，这样一开始打字它就藏起来。

**觉得译文出现得慢？**
调小「停顿判定（毫秒）」（默认 300，可以试 150～200）。
另外确认「流式输出」是开着的——它让译文的第一个字提前 100 ms 以上出现。

**开机后右下角没看到状态球？**
先运行 `main.py --running` 看工具在不在，`main.py --autostart-status` 看自启项还在不在。
某些安全软件 / 系统优化工具会清掉启动项，这时重新双击 `autostart-on.bat` 即可。
确认启动过程有没有报错：看 `logs/app.log` 里有没有「桌面已就绪，开始启动」。

**打中文没反应？**
先确认工具在跑（右下角有状态球），再确认焦点在真正的输入框里。
某些应用（游戏、部分 Electron 应用、终端）不通过 UI Automation 暴露文本，
这时用 `Ctrl+Alt+T` 手动翻译选中文字。

**打字时悬浮窗不出来，但 `Ctrl+Alt+T` 能用？**
说明读取这一环没问题，是触发没到。把「停顿判定」调小一点（比如 600ms），
确认「停止打字后自动翻译」是勾上的，且文字里确实有中文（纯英文会被「原文本无中文则跳过」拦掉）。

**弹出「本机翻译服务没在运行」？**
右键状态球 → 「启动本机引擎」，等顶部状态球变回「待机」即可。
工具启动时也会自己拉起 Ollama，但如果你在它还没就绪时就开始打字，会先看到这个提示。

**想让它翻译更快 / 更少打扰？**
调大「停顿判定」毫秒数（比如 1200），或调大「两次翻译最小间隔」。

**悬浮窗挡住了输入框？**
把「出现位置」改成 `fixed` 并设一个固定坐标，或者按住悬浮窗直接拖到顺手的位置。

**只想翻译某个段落，不想自动触发？**
把「停止打字后自动翻译」关掉，只用 `Ctrl+Alt+T`。

**模型返回的是解释而不是译文？**
换个更听话的模型（qwen2.5-instruct 系列比较稳），或把翻译风格改成 `literal`。

**重装 / 卸载 Ollama？**
`ollama` 卸载程序位于 `%LOCALAPPDATA%\Programs\Ollama\unins000.exe`。
模型文件在 `E:\OllamaModels`，卸载不会删掉它们。

## 隐私

- 翻译请求只发往你在设置里填的地址，默认是 `127.0.0.1:11434`，且**强制绕过系统代理**
- 没有遥测、没有统计上报、不加载任何第三方脚本
- 唯一会联网的时刻是 `首次安装.bat` 里 pip 安装依赖
- 翻译结果只在内存里做 LRU 缓存（最多 300 条），不落盘

## 文件说明

| 文件 | 作用 |
|---|---|
| `main.py` | 入口，装配所有部件；含 `--probe` / `--test` / `--engine` / `--running` / `--set-autostart` 等命令行 |
| `restart.py` | 重启工具（结束旧实例后重新拉起，脱离当前命令行会话） |
| `autostart.py` | 开机自启开关（读写注册表 Run 项）、登录时等待桌面就绪 |
| `config.py` | 配置默认值、深度合并、读写 |
| `context_reader.py` | 读取焦点输入框文本（UIA → Win32 两级降级）+ 选中文本 |
| `engines.py` | 翻译后端（含流式）、本机服务探测、模型自动挑选、Ollama 进程管理 |
| `overlay.py` | 双语悬浮窗、状态球、瞬间弹出与流式刷新 |
| `watcher.py` | 全局键盘监听与防抖 |
| `settings_ui.py` | 设置窗口（按配置表自动生成表单） |
| `config.json` | 你的实际配置（首次运行自动生成） |
| `启动.bat` / `调试启动.bat` / `重启.bat` | 启动 / 带控制台启动 / 重启 |
| `autostart-on.bat` / `autostart-off.bat` | 开启 / 关闭开机自启 |
| `.venv/` | 独立虚拟环境，不污染系统 Python |

> 批处理里凡是**给用户看的中文**都用 GBK 存（`启动.bat`、`调试启动.bat`、`首次安装.bat`、
> `autostart-on.bat`、`autostart-off.bat`）；纯内部调用的 `install.bat` / `start.bat` / `debug.bat`
> 保持纯 ASCII。Python 侧的命令行输出一律 ASCII 键值，避免管道/重定向时编码错乱。
